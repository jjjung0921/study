# RAG 초안 사실 대조

대상: `drafts/rag-sequence-token-marginalization.pre-humanize.md`  
대조 자료: 지정된 RAG v4 원문 텍스트와 `conversation.json`의 관련 문답만 확인. 초안은 수정하지 않았다.

## 주장별 판정

| 초안 위치 | 판정 | 근거 및 제안 |
|---|---|---|
| 21–27행, 「문제」 첫 문단 | **문제 — 개인 생각을 기록보다 강하게 서술** | “처음에는 검색한 문서들의 정보를 합쳐 답변을 만든다고 생각했다”는 내적 믿음은 QA 기록에 직접 나오지 않는다. 기록에는 parametric/non-parametric memory의 구분 질문(E018)과 문서별 출력을 벡터로 더하는지에 대한 질문(E032, E044)이 있다. “처음에는 문서별 정보를 어떻게 결합하는지 질문했다”처럼 확인 가능한 질문으로 바꾸는 편이 안전하다. 반면 뒤의 “문답에서도 같은 지점을 여러 번 확인”은 E032·E044·E049의 질문으로 뒷받침된다. |
| 31–47행, 메모리와 입력 결합 | **PASS** | parametric memory를 BART 파라미터, non-parametric memory를 문서 인덱스로 설명하고, 질문과 각 passage 텍스트를 결합하는 구분은 원문 §2.2–2.3(166–187행)에 부합한다. top-K passage를 하나의 긴 입력으로 합친다고 하지 않은 점도 정확하다. |
| 51–114행, 두 수식·스칼라 설명·재검색 여부 | **PASS** | RAG-Sequence는 한 문서에 조건부인 전체 출력 확률을 문서별로 가중 합산하고, RAG-Token은 위치별 다음 토큰 확률을 먼저 합산한 뒤 곱한다(원문 §2.1, 142–164행). 주어진 후보 토큰의 확률은 스칼라이고, 어휘 전체에 대해 계산하면 다음 토큰 분포 벡터가 된다는 설명은 수식과 일치한다. 두 식에서 검색 후보와 $p_\eta(z\mid x)$는 동일한 입력 $x$에 조건부이므로 매 토큰마다 전체 인덱스를 다시 검색한다고 해석하지 말라는 설명도 타당하다. |
| 118–182행, 수치 예제·EOS·$N=1$ | **PASS** | 계산 결과가 맞다: Sequence $0.6(0.8·0.9)+0.4(0.3·0.2)=0.456$, Token $(0.6·0.8+0.4·0.3)(0.6·0.9+0.4·0.2)=0.372$. 확률 벡터 혼합 결과도 각각 $(0.60,0.26,0.14)$, $(0.19,0.19,0.62)$로 맞는다. 예제를 가상 토큰 `서울`과 EOS 두 위치로 명시했으므로 실제 토크나이저에 대한 사실 주장도 아니다. $N=1$에서는 두 식이 같다는 결론은 §2.1 163–164행 및 QA E049·E050과 일치한다. |
| 186–207행, 감독·목적함수·optimizer | **PASS** | 입력/목표 출력 쌍에 대한 negative marginal log-likelihood, 검색 문서의 직접 감독 부재, document encoder와 인덱스 고정 및 query encoder·BART 업데이트는 원문 §2.4(189–201행)에 맞다. 원문 표현은 “stochastic gradient descent with Adam”이며, 이를 별개의 SGD·Adam 설정 둘로 나누지 않은 것도 정확하다. |
| 211–234행, 디코딩과 Appendix A | **PASS** | Token 혼합 분포를 표준 beam decoder에 넣는 점, Sequence의 문서별 후보 탐색과 Thorough/Fast 근사는 §2.5(203–221행)와 부합한다. Appendix A의 test 설정도 정확하다: QA는 Token K=15, Sequence K=50, greedy 및 Thorough; Open-MSMarco와 Jeopardy는 양쪽 K=10, beam size 4 및 Sequence Fast(970–976행). QA에서 beam search가 개선을 주지 않아 greedy를 썼다는 설명도 원문에 명시돼 있다. |
| 238–252행, Table 5 다양성 | **PASS** | 표의 distinct/total trigram 비율은 원문 Table 5(원문 471–482행)와 일치한다. 문서 내부 어휘나 decoding이 차이를 만들었다는 것은 가설로 한정했고, 원인을 확정할 통제 실험이 논문에 없다고 한 것도 §4.5(447–452행) 범위를 넘지 않는다. |
| 253–254행, FEVER 평가와 Appendix E | **PASS** | §4.4는 검색 문서 제목과 gold evidence article의 overlap을 보고하며 top-1 71%, top-10 90%를 제시한다(원문 437–443행). Appendix E는 claim을 다시 생성한 뒤 마지막 hidden state로 분류하고 문서 간 주변화한다고 설명하고, 근거 문장 추출은 다른 하위 과제이며 다루지 않았다고 밝힌다(1040–1047행). 초안은 기사 수준 평가와 문장 추출 경계를 구분했고, 실제 절차와 §2.1의 길이 1 추상화를 혼동하지 않았다. |
| 266–273행, 결론·참고문헌 | **PASS** | “수식의 표현력, 탐색 방식, 실험 관측은 각각 확인해야 한다”는 결론은 본문에서 구분한 범위와 맞는다. 재현을 수행했다는 주장도 없다. |

## 미검증

- 이 검토는 지정된 원문 텍스트와 QA 기록의 관련 구간만 대상으로 했다. 논문 공식 구현 코드나 별도 실행 결과는 확인하지 않았다.
- 초안의 수치 예제는 자체 산술로 대조했다. 논문 수치의 재현이나 모델 동작 실험은 아니다.

## 우선 수정 제안

1. 21–22행의 “처음에는 … 생각했다”를 QA에서 확인되는 질문의 형태로 낮춰 쓴다. 나머지 검토 범위에서 별도 실질 오류는 찾지 못했다.

교정 이력: 기존 대화 참조의 39·175·413·608–613행은 conversation.json의 실제 행 위치가 아니어서 E018·E032·E044·E049·E050으로 교체했다. JSON의 evidence_id 위치는 각각 180·320·440·490·500행에서 확인했다.
